# In-memory server key-load timing
Fixed before execution. Use SEAL 4.7.2, BFV N=8192, coefficient bits 60/60/60, t=65537, tc128. Each of ten processes builds client and server contexts, creates one fresh client secret and fresh evaluation key sets, serializes all twenty buffers, and visits all twenty in each of five individually shuffled rounds. The first round warms the allocator and verifies every rotation on both complete rows. The remaining four rounds time only public buffer GaloisKeys::load into an empty destination object, using steady_clock in nanoseconds. Timing includes validation and seeded expansion inside load. Timing excludes destination construction/destruction, key generation, serialization, networking, context and evaluator initialization, and post-load correctness checks. Buffers are reused across rounds. Each process owns a distinct deterministic ordering; the crypto randomness is independent. Summarize the median of each process's four samples, then take the median across ten process medians. Do not infer cold-start or network latency from this benchmark.
