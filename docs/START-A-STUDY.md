# Starting a study

Before collecting data, date the following brief in a local or private workspace. Open a public issue when you want public feedback. Keep it small enough that another person can challenge one specific claim.

1. **Question and audience.** Who would use the answer, and what would they do differently?
2. **Closest prior work.** Name the strongest existing result or baseline; specify the difference you intend to test.
3. **Prediction or theorem.** Record the statement, assumptions, comparison and result that would make you abandon or narrow it.
4. **First independent check.** Specify a counterexample search, separate verifier or held-out setting. For measurements, define the timing boundaries and the independent sampling unit before the run.
5. **Evidence to keep.** Pin source revisions, inputs and commands; separate raw observations from summaries. Include an explanation of what a successful replay does and does not verify.

Start code under `projects/<short-name>/`. Promote a study to its own repo when one question has a self-contained result and a reproducible entry point. Leave an index link here, keep the evidence in one maintained place, and cite immutable commits for prior versions.
